# PPT 审核试验记录：2026-11-17

## 结果和适用范围

项目已具备显式的“独立审稿 → 定点修订 → 独立复审”文本流程。在一个人工构造的 8 页幼教样本中，三个分别启动、上下文独立的对话 Agent 完成了这条流程：首次审稿提出 4 条阻断意见，涉及第 3、5、6 页；修订只改这 3 页；复审没有报告剩余阻断问题，程序返回 `passed`。

这是 **ChatGPT Linux 工作区中的构造样本演示**。Agent 的结构化结果经临时文件交换送入实际的 `review_kindergarten_content` 服务，由该服务验证证据、限制改动、执行硬规则和决定状态。没有调用项目实际的 DMX/OpenAI-compatible 模型 API，没有在用户 Windows 电脑执行，也没有处理真实生成的 PPT 或实际渲染图。不能将本记录写成线上准确率、真实课程合格率或生产性能提升。

## 样本中具体改了什么

样本面向 4—5 岁幼儿，主题是观察比较海龟、海豚和章鱼的可见身体特征。原要求明确采用指认、描述和比较，不要求书写分类术语，不展开植物生长活动。

| 页面 | 原稿问题 | 实际采用的修订 |
| --- | --- | --- |
| 第 3 页 | 教学文字讲海豚，配图描述却要求豆子在泥土里发芽，并明确没有动物 | 仅将配图描述改为完整海豚观察图，要求背鳍、尾鳍清晰可辨，主体不裁切、不遮挡 |
| 第 5 页 | 活动突然变成给豆子种植、浇水 | 改成指认海龟的壳、海豚的鳍、章鱼的腕；同步修订本页目标、画面文字、幼儿指令、教师引导和配图要求 |
| 第 6 页 | 要求幼儿写出“爬行纲、哺乳纲、头足纲”，全部写对才能继续 | 改为选择两种动物、指认并口头说出一处差异；教师接受手势或简短表达，取消全员书写正确的推进条件 |

第 1、2、4、7、8 页的完整结构保持不变；课程 `meta`、`lesson_goals`、`lesson_arc`、页数和页序保持不变。程序硬规则在修订前后均未报告错误。

当前流程完成了 1 轮修订复审，共 3 次 Agent 调用尝试。实际记录耗时约 175 秒，包含工作区调度和文件等待，不代表后端模型速度。该通道没有返回可核对的模型标识、Token 消耗或费用，因此这些值为未知，不能计作零成本。

## 试验发现并修正的问题

### 1. 对应删除的跑题内容重复索要来源

第一次试跑中，审稿者识别了三页主要问题，同时把原任务已经排除的植物生长和分类知识判为需要补充来源，返回 `needs_human`，没有进入修订。该结果没有被改写为通过。

随后细化审稿规则：对于原要求明确排除、可以直接删除或改回已有资料支持内容的段落，不必先证明它的真伪；原任务必须保留或补入的关键事实仍须有依据，资料不足仍应停下确认。使用新规则和新的独立审稿上下文重新完整试跑，才取得上文的修订结果。

两次运行共发生 4 次工作区 Agent 调用：首次停下的审稿 1 次，调整后的完整流程 3 次。它们不等同于项目实际模型 API 的调用或账单。

### 2. 修订可能删除教学契约来获得“通过”

独立代码复核发现，修订若删除游戏规则或把受保护页面改成普通页，可能让原有检查不再适用。新增约束会保留受保护教学角色、游戏身份和必需配图要求，并拒绝用删除契约掩盖问题。已有专门回归覆盖此路径。

### 3. 命令输出失败可能触发重复提交

英文 Windows 重定向输出可能采用不能编码中文的字符集；原来的清锁顺序也可能在回执写出前解除保护。现已显式使用 UTF-8，并在回执完整写出及刷新后才清除在途锁；写入、刷新失败及 HTTP 响应截断都会保留不确定状态。回归检查确认再次运行不会再次提交 API。
