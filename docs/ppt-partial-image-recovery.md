# PPT 缺图提示与局部补图

## 完成状态

完整课件任务把页面可用性与图片完成度分开判断：

- 页数与可见正文完整时，任务状态返回 `completed`，并始终保留 `data.presentation_id`，调用方应提供“打开课件”入口。
- 有缺图时，`data.stage` 为 `completed_with_warnings`，`data.has_warnings` 为 `true`，具体说明位于 `data.warnings`，缺图页码位于 `data.missing_image_pages`。这是可打开课件，不能显示为整套生成失败。
- 只有零页面、页数未写完或页面没有可见正文时，任务才返回 `error`。
- 图片服务在流末尾超时，但数据库里已经存在完整页面和正文时，也按可打开课件处理，并把超时作为提示保留。

外层 TeachNova 页面可直接使用 `status=completed` 和 `data.presentation_id` 打开课件，同时展示 `message` 或 `data.warnings`。不要仅因 `has_warnings=true` 改成“重新生成整套 PPT”。

## 教学质量未通过

自动生成没有老师确认步骤，因此与普通缺图区分处理：

- 当排序漏项、分类对应冲突、题目与揭晓答案不一致等硬性检查未通过时，先保存大纲，停止页面与生图请求。
- 同步 prepare 返回 HTTP 422，`detail.code=KINDERGARTEN_PLAN_REVIEW_REQUIRED`，保留 `presentation_id`、`outline_path` 和逐页 `quality.errors`。
- 异步任务返回 `status=error`、`data.stage=review_required`，同样保留上述入口与质量报告。调用方应显示“检查大纲”，链接到 `outline_path`；此时尚无完整 PPT，不能显示“打开课件”。
- 不通过自动添加答案选项、删除游戏契约或重复付费请求掩盖错误。仅当揭晓正文已经支持题目的答案、选项字典一致时，允许修正错误的内部答案编号。
- 可编辑大纲路径继续保留供老师核对。本轮自动阻断适用于无人工审核的 prepare/完整生成路径，不代表系统已经能自动判定全部教学事实正确。

本轮本地环境没有模型服务凭据、可用远程测试地址与 Linux 导出转换器。代码回归包含真实 SQLite 中的大纲和任务保留、停止后续生成的检查；不代表已经通过真实生图、PowerPoint 或 WPS 成品验收。

## 编辑器补图

编辑器读取缺图位置，并展示页码及“补齐缺图”按钮。补图遵循以下规则：

- 只为仍是空地址或占位图、且保留原提示词的图片位置调用生图接口。
- 相同课件同时只能有一个补图任务；重复点击返回现有任务，不重复提交 DMXAPI。
- 每完成一个图片请求就写入数据库；刷新或关闭页面不会丢掉已完成图片。
- 补图开始前先保存老师修改；补图期间暂停编辑和自动保存。
- 任务完成后只合并新图片地址，不覆盖标题、正文、备注、元素位置和撤销记录。
- 老师已手动换图或修改图片提示词时，老师的版本优先。
- 服务中断后保留成功图片，任务显示可继续补图，不自动重试付费请求。

接口：

- `GET /api/v1/ppt/presentation/{id}/image-repair`：缺图页码、任务状态和进度。
- `POST /api/v1/ppt/presentation/{id}/image-repair`：启动或取得当前补图任务。

补图仍使用现有图片并发队列和 DMXAPI 超时策略。供应商返回超时不能证明远端任务取消，因此系统不会自动重复提交。

## 已有坏图的单张替换

编辑器图片提示区现在可按页选择一张已有图片，预览后点击“重新生成这张图”。空请求体仍表示只补缺图；单张替换使用同一个 POST 接口，JSON 请求体为 `{ "key": "GET 返回的图片 key", "expected_url": "GET 返回的当前图片地址" }`。

- GET 新增 `replaceable` 图片列表、逐张 `missing[].reason`，以及 `replacements` 完成事件。
- 替换任务只清空后台副本中的目标地址，数据库和画布继续保留原图；不同时生成其他缺图。
- 新图成功生成并完成构图处理后，才更新目标图片地址，并设置完整显示、取消旧裁切缩放；仅在显式启用语义质检时额外检查画面。标题、正文、备注、图片框的位置和尺寸保持不变。
- 图片、提示词或目标元素在生成期间被改动时，放弃替换。完成结果与延迟自动保存之间有图片版本标记，避免旧地址把新图覆盖回去；收到新结果后仍允许老师手动换图和撤销。
- 缺图与单张替换共用同一课件任务锁；重复点击不会另起任务。支持行锁的数据库中，编辑保存和补图落库还会短暂锁定同一课件记录，锁内不请求图片服务。多实例全局生图限额仍需分布式队列验证。
- 替换失败仅表示这张新图未采用，原课件与原图仍可使用。

## 图片检查与构图修复

- 2026-09-18：自定义图片语义质检暂时停用，`ASSET_SEMANTIC_QA_ENABLED` 缺省或 `false` 时，首次生成、补图与单张替换均不调用质检，不因质检结论丢弃图片或自动重画。旧环境里的 `ASSET_SEMANTIC_QA_PROVIDER=auto/dmx` 不会重新开启检查。图片提示词、构图处理、登录鉴权和供应商审核继续保留。
- 后续校准后可显式设置 `ASSET_SEMANTIC_QA_ENABLED=true` 恢复检查：确定性画面质量失败首次生成最多重试一次；补图与单张替换不重试。质检服务超时/异常保留已生成图片并记录警告。不自动重复供应商超时或审核拒绝的请求。
- 普通图片框检查原始图片，避免补白掩盖原图边缘已经截断的主体；背景和抠图检查相应最终结果。视觉检查提高输入细节和 JSON 输出额度。
- 教研场景图片框不再采用约 5.5:1 的细横条或 300×430 的窄框。左图、右图、上图与正文扩展构图保留不同位置，优先完整显示；文字放不下仍走容量检查和安全版式选择。
- 这些几何调整适用于新创建的页面。已保存课件不会因更新模板自动重排；单张替换也不会擅自扩大老师的图片框。原文件已裁掉的身体部位需要重新生成，不能靠切换显示模式恢复。

本轮已用真实 SQLite 验证单张替换成功、质检失败、未配置质检、重复点击、老师修改优先及延迟保存；并用实际 HTML 导出渲染器检查 3 个教研模板包的 11 种场景构图。渲染使用边界测试图，不代表真实 AI 配图验收。DMXAPI 实际成功率、远程多人使用与 PowerPoint/WPS 打开结果仍需在真实环境验证。

### 本地完整流程复测发现与修复

新增 `engine/api/tests/test_research_ppt_flow.py`，通过 HTTP 接口运行真实父子任务、独立 SQLite、图片持久化、课件重新打开及补图。模型规划/正文输出和生图供应商使用可计数的本地替身，不读取业务数据库、不产生模型费用。

本次复测额外修复：

- 图片失败标记会阻止自动重画，但完成检查误把这些图片排除，导致缺图仍提示全部完成。现按包含失败标记的缺图清单报告页码。

- 取消教研父任务未取消内部生图任务。现联动取消课件子任务，关闭生成流时清理内部图片任务，并等待本地 worker 退出；已在供应商执行的请求不承诺撤回计费。
- 大纲规划返回后可能覆盖已取消状态。现重新读取状态再启动课件；对子任务 ID 尚未写入课件元数据的短暂窗口，也按所属课件查询并取消子任务。
- 取消链路中字符串课件 ID 写状态的问题，统一转换为 UUID。
