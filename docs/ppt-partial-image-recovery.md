# PPT 缺图提示与局部补图

## 完成状态

完整课件任务把页面可用性与图片完成度分开判断：

- 页数与可见正文完整时，任务状态返回 `completed`，并始终保留 `data.presentation_id`，调用方应提供“打开课件”入口。
- 有缺图时，`data.stage` 为 `completed_with_warnings`，`data.has_warnings` 为 `true`，具体说明位于 `data.warnings`，缺图页码位于 `data.missing_image_pages`。这是可打开课件，不能显示为整套生成失败。
- 只有零页面、页数未写完或页面没有可见正文时，任务才返回 `error`。
- 图片服务在流末尾超时，但数据库里已经存在完整页面和正文时，也按可打开课件处理，并把超时作为提示保留。

外层 TeachNova 页面可直接使用 `status=completed` 和 `data.presentation_id` 打开课件，同时展示 `message` 或 `data.warnings`。不要仅因 `has_warnings=true` 改成“重新生成整套 PPT”。

## 编辑器补图

编辑器读取缺图位置，并展示页码及“补齐缺图”按钮。补图遵循以下规则：

- 只为仍是空地址或占位图、且保留原提示词的图片位置调用生图接口。
- 相同课件同时只能有一个补图任务；重复点击返回现有任务，不重复提交 DMXAPI。
- 每完成一个图片请求就写入数据库；刷新或关闭页面不会丢掉已完成图片。
- 补图开始前先保存老师修改；补图期间暂停编辑和自动保存。
- 任务完成后只合并新图片地址，不覆盖标题、正文、备注、元素位置和撤销记录。
- 老师已手动换图或修改图片提示词时，老师的版本优先。
- 服务中断后保留成功图片，任务显示可继续补图，不自动重试付费请求。

接口：

- `GET /api/v1/ppt/presentation/{id}/image-repair`：缺图页码、任务状态和进度。
- `POST /api/v1/ppt/presentation/{id}/image-repair`：启动或取得当前补图任务。

补图仍使用现有图片并发队列和 DMXAPI 超时策略。供应商返回超时不能证明远端任务取消，因此系统不会自动重复提交。
