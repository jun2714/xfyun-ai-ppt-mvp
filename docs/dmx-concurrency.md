# 多教师生成与 DMXAPI 超时处理

本轮在 15fc416 的完整课件后台接口、落库检查、中文配图约束之上补充请求调度。

## 当前实现边界

- 同一个 API 进程的课堂、教研、编辑器生图入口共享图片额度，默认同时请求 2 张，每位已登录老师最多 1 张；关闭 ENABLE_PARALLEL_IMAGE_GENERATION 时仍按 1 张串行。
- 幼教大纲独立额度：默认同时 4 个，每位老师 1 个。此额度不覆盖所有通用聊天/幻灯片文字接口。
- 两类队列分别最多等待 32 个请求，每位老师最多排队 8 个。按老师轮转，避免一位老师连续占用全部请求机会。
- 排队默认最多 180 秒；图片实际请求默认 150 秒，从获得额度后开始计算。排队失败时不调用供应商。已取消的等待任务释放额度。
- 超时、429、服务错误不会自动重复付费生图；只有确认图片语义不符才保留一次原有局部修正。完整课件错误不会删除已有页并自动重做。
- 完整课件接口检查保存页数、每页正文和缺图情况，缺图时保留页面及项目入口，提示缺图页码，不标记完全成功。

## 区分本地和供应商问题

查看 `/api/v1/ppt/diagnostics/image-runtime` 的实际模型、超时、global_concurrency、per_owner_concurrency、max_pending_requests、queue_timeout_seconds 和 admission_scope。修改额度配置后重启进程。

日志的 `Model request admitted` 包含 lane、queue_wait_seconds、active；不打印老师身份或课件正文。图片 trace 区分 image_queue_full、image_queue_timeout 和 image_request_timeout。前两项是本地未提交；最后一项是客户端等待供应商超过时限。

DMX 控制台的 8 分钟耗时不能单独证明是本地排队、供应商排队还是上游计算。需对照应用实际提交时间、供应商请求记录、返回状态和通道，确认相同请求。客户端关闭连接不构成供应商任务取消或退款保证。本轮没有修改 DMX 模型、接口地址，也不声称修复供应商通道。

## 多进程与扩容

这些额度不是跨机器的账户总额度；4 个 worker 配置 2，会允许最多 8 个图片请求。没有登录身份的请求共用匿名额度。不要把单进程并发测试当作多副本生产压测。

现有后台任务仍运行在应用进程里，不是可靠的持久任务执行器；进程重启后的自动恢复、跨副本幂等和租约回收尚未实现。扩大到多个 worker/副本之前，需要共享队列与分布式额度（如 Redis + worker），以项目和图片位置作为幂等键，持久保存排队/执行/部分完成状态，并通过 DMX 实际通道压测确定额度。提高配置值本身不会提高供应商的处理能力。

## 本地验收

并发测试使用模拟供应商，不消耗 DMX 额度。覆盖多教师共享额度、轮转、队列满、排队超时、取消竞争、文字/图片隔离、超时不重试，以及缺图不报完整成功。实际 DMX 高峰吞吐和延迟需要另行验证。
