# 幼儿园 AI PPT 模板库与图片生产方案

## 1. 目标

系统面向幼儿园全部常见演示场景，而不是只支持认知课或家长会。用户输入 Brief，确认大纲后，系统根据每页内容关系选择模板构图，生成可在线编辑、可导出、可被 WPS/PowerPoint 打开的 PPTX。

生产代码不得用主题关键词、固定页码或页面位置决定业务内容和构图。模板可以固定，业务内容、页数、页面顺序、页面角色与布局映射不得写死。

## 2. 最终生产链路

```text
Brief
→ 文本模型生成大纲与逐页内容契约
→ 用户确认大纲
→ 模板族筛选
→ 模型逐页选择符合契约的布局
→ 锁定布局
→ 按布局 JSON Schema 生成内容
→ Schema 与容量校验
→ 全稿素材规划
→ 仅生成最终会被消费的图片
→ 本地 OCR / 尺寸 / 透明度检查
→ 模板 hydration
→ Presenton 编辑器
→ PPTX 导出
→ 本地结构、渲染与视觉门槛
→ 正式下载
```

页面数量完全来自确认后的大纲。系统不规定封面、目录、结束页，也不假设第一页或最后一页的语义。模型可以在内容需要时产生开场、过渡、提问、反馈、揭晓、总结等语义，但代码只处理通用内容契约。

## 3. 模板不是固定流程

模板保存的是可复用设计能力：字体、色彩、形状、层级、图文比例、内容容量和媒体槽位。模板不保存某个主题的固定文案、固定故事流程或固定页数。

每个布局必须声明：

```json
{
  "capabilities": ["single-focus", "question"],
  "contentShape": {
    "minItems": 1,
    "maxItems": 3,
    "textBlocks": 2,
    "imageSlots": 1
  },
  "media": {
    "backgroundSlots": 0,
    "framedImageSlots": 1,
    "cutoutSlots": 0,
    "required": false
  },
  "readability": {
    "minimumFontSize": 24,
    "maximumVisibleCharacters": 90
  },
  "qualityStatus": "passed"
}
```

内容契约描述当前页真实需要的关系、项目数、可见字符数和媒体角色。选择器只能从满足契约的布局中选择。模型返回非法索引、数量不符或不兼容布局时直接失败，不随机兜底。

布局锁定后，内容不适配时必须重新选择布局并重新生成该页内容，不得把 A 布局的字段塞入 B 布局。

## 4. 首批模板族

模板族不是业务类别映射。受众、氛围与可读性用于筛选模板族，逐页内容契约用于选择布局。

### 4.1 明亮童趣

适用于幼儿课堂、认知、互动、活动和游戏。使用明亮配色、大字号、圆角形状和高视觉占比。不得依赖固定主题素材。

### 4.2 温暖自然

适用于故事、艺术、自然观察、成长记录和温和课堂。使用自然色、插画边饰、留白和柔和层次。

### 4.3 清晰专业

适用于家长会、教研、园务汇报和教师培训。使用清晰层级、图表、比较、流程、行动项和数据构图；仍需保证中文阅读距离。

每族目标 24–36 个通过验收的布局，至少覆盖开场、单主题、图文、多项、比较、顺序、提问/揭晓、总结/行动等设计能力。数量是模板库建设目标，不是任何 PPT 的固定页数。

## 5. 外部模板来源与许可

只允许导入许可清晰、允许改编并满足分发条件的来源。

- Presenton 自带模板：Apache-2.0，可作为专业模板和引擎能力基线。
- SlidesCarnival：CC BY 4.0，可改编和商用，必须保留合理署名与来源链接；不得把未修改模板作为独立商品原样转售。
- SlidesMania：其条款禁止将原版或修改版作为模板下载或数据库内容再次分发，因此不进入产品模板库。
- 许可不清晰、禁止再分发或只允许个人使用的模板一律不导入。

每个导入模板必须记录来源页面、下载日期、许可证、署名文本、原始文件哈希、保留/删除页码和修改说明。生成稿使用第三方模板时，在演示文稿末页或元数据中保留符合许可证要求的署名。

候选 PPTX 不直接成为生产模板，必须经过：

```text
下载到隔离目录
→ 病毒与 OOXML 结构检查
→ WPS/PowerPoint 渲染
→ 逐页截图
→ 删除资源说明页、示例内容页和不合格页
→ 抽取通用构图
→ 标注可编辑文本/图片/形状
→ 生成布局 Schema
→ 中文长短文本 hydration 测试
→ 再次渲染验收
→ qualityStatus=passed
```

### 5.1 当前候选审查结论

- `Memphis Playful Education`：20 页，配色和形状统一；成人照片、使用说明、资源页和署名页不能成为普通内容布局。只允许抽取通过字号和内容容量检查的构图。
- `Animal Habitats Science Lesson`：21 页，包含比较、分类、匹配等有价值构图；多页存在 Lorem Ipsum、过小正文、裁切和过密元素，禁止整套原样导入，只保留修复并复验的布局。
- `Welcome to Our Pre-K Family`：16 页，幼儿风格统一但能力覆盖不足，只能作为模板族的一部分，不能单独冒充完整模板库。
- Presenton `dynamic` 和 `momentum` 实际为商务风，不得仅改名字后标成幼儿模板；`executive` 可作为清晰专业族候选。

## 6. 图片生产策略

图片必须先由全稿素材规划器统一规划，再执行生成。逐页内容生成阶段不得立即生图。

每个图片槽只能使用以下角色：

```text
background     整页场景背景
framed-image   有边界的照片或插画
cutout         透明背景主体
```

每个槽位必须声明角色、比例、填充方式、安全区、是否必需、复用组和生产模式。生产模式为：

```text
direct-background  直接生成完整背景
composite-image    一张图内包含多个彼此有关系的主体
sprite-sheet       一张图内生成 2–6 个相互独立素材，再由程序切割
single-cutout      单个透明主体
reuse-or-search    优先复用或使用已提供素材
```

### 6.1 图片中禁止文字

默认所有生成图片都禁止可见文字、字母、数字、标签、Logo、水印和伪文字。中文标题、题目、选项、标签和说明必须由 PPT 文本框渲染，不能让图片模型绘制。

Prompt 使用什么语言与页面显示什么语言是两件事。即使图片 Prompt 为英文，仍必须明确禁止画面文字。生成后使用 Windows 本地 OCR 检查；检测到任何文字时只重试该图片一次，第二次仍失败则阻断，不使用带英文烙字的图片。

只有用户明确要求把文字作为画面内容且模板槽声明豁免时，才允许文字图；首批幼儿园模板不设置此豁免。

图片请求必须同时携带 `presentationLanguage` 和 `visibleTextPolicy`，不能只依赖 Prompt 的自然语言：

```json
{
  "presentationLanguage": "zh-CN",
  "visibleTextPolicy": "forbidden",
  "allowedVisibleText": [],
  "ocrPolicy": "block-on-detection"
}
```

首批生产规则固定为 `visibleTextPolicy=forbidden`，这不是把中文内容写死，而是将可编辑文字与不可编辑像素图分离。OCR 检出英文、中文、数字或伪文字时均视为失败；程序不得通过模糊、遮盖或裁掉文字的方式伪装通过。

### 6.2 整图与素材图的选择

- 场景氛围是主要信息、人物与环境需要融合、或图片覆盖大部分页面时，使用 `background` / `direct-background`。
- 多个主体构成同一叙事或比较画面，且不需要分别编辑时，使用 `composite-image`。
- 2–6 个主体需要分别放入选项、匹配或分类槽，且风格必须一致时，使用 `sprite-sheet`。
- 单个主体需要自由移动、缩放或复用时，使用 `single-cutout`。
- 用户已提供素材或同一图片可跨页复用时，优先 `reuse-or-search`，不重复生成。

不能依据主题关键词猜测图片角色。角色来自锁定布局的槽位声明和内容契约。

### 6.3 多素材合图省钱的条件

用户提出“一张图生成多个动物，再由程序抠图”是正确的省钱方向，但只在满足以下条件时执行：

- 2–6 个独立主体；
- 同一画风、光照和视角；
- 每格主体之间无接触、无遮挡；
- 纯色且颜色与主体边缘差异明显的背景；
- 固定 2×2 或 2×3 网格；
- 不含阴影跨格、文字、边框和装饰；
- 最终布局确实消费所有切出的主体。

程序按固定网格切割，并仅移除与图片边缘连通的纯色背景。输出必须通过透明度、空图、主体触边、尺寸和边缘质量检查。复杂场景、毛发与背景颜色接近、半透明物体或只有一个主体时，不使用绿幕合图。

这样可以把多个独立生成请求合并为一次，但不能为了省钱把不相关素材硬塞到一张图，也不能保留未被页面消费的付费结果。

`sprite-sheet` 请求必须在生成前形成可追踪的素材清单，生成后逐项核对，禁止依靠模型自由发挥：

```json
{
  "grid": "2x3",
  "background": "solid-chroma",
  "subjects": [
    { "assetId": "asset_1", "label": "仅供校验，不进入画面", "consumerSlots": ["slide_3.option_1"] },
    { "assetId": "asset_2", "label": "仅供校验，不进入画面", "consumerSlots": ["slide_3.option_2"] }
  ]
}
```

切割后必须核对：输出数量等于请求数量、每格只有一个主要连通主体、主体未触边、背景已去除、每个输出都有消费者。任何一项失败时，只允许把失败主体降级为 `single-cutout` 并重试一次；不得重新生成已经合格的主体，也不得重新跑整张 PPT。

“绿幕”只是纯色背景的一种，不固定使用绿色。规划器应根据主体主色选择反差最大的候选背景色，避免绿色动物、半透明边缘或细毛发出现色溢。程序只移除与画布边缘连通且颜色落在阈值内的背景区域，不能删除主体内部的同色区域。

### 6.4 图片模式决策表

| 页面真实需求 | 生产模式 | 是否切割 | 典型用途 | 禁止情况 |
|---|---|---:|---|---|
| 人物与环境共同表达一个场景 | `direct-background` | 否 | 故事场景、活动氛围、大视觉开场 | 需要分别移动每个主体 |
| 多个主体共同构成一个不可拆叙事 | `composite-image` | 否 | 一群动物、亲子互动、场景比较 | 后续需要配对或分别反馈 |
| 2–6 个独立主体分别进入槽位 | `sprite-sheet` | 是 | 选项、分类、配对、找不同素材 | 主体相互遮挡、半透明或最终不会全部使用 |
| 单个主体需独立编辑或跨页复用 | `single-cutout` | 视输出而定 | 角色、物品、动物贴纸 | 可以直接复用现有合格素材 |
| 用户素材或已生成素材满足需求 | `reuse-or-search` | 否 | 跨页复用、上传素材 | 为追求变化而重复付费生成 |

选择依据是锁定布局的槽位数量、槽位角色和编辑需求，不是“认识动物”“家长会”等主题关键词。文本模型只输出媒体需求；确定性规划器依据上表生成生产计划，因此不会把业务主题映射写死在代码里。

### 6.5 封面和结束画面

整页铺满不是按“第一页/最后一页”写死的规则。只有当内容契约要求场景型开场或收束，且模型选中了 `background` 布局时，图片才全屏铺满并使用 `cover`。文字安全区由模板提前声明。

如果某份 PPT 没有开场或结束语义，就不强行插入。若开场适合纯形状与大标题，也可以完全不生图。

## 7. 费用与重试

- 大纲未确认前不生图。
- 布局未锁定前不生图。
- 全稿只生成最终被图片槽消费的素材。
- 相同 Prompt、角色、比例和风格可跨页复用。
- Sprite sheet 每次最多 6 个素材。
- 单个失败素材最多自动付费重试一次。
- 单页或单图失败不得重跑整稿。
- 每次调用记录请求 ID、模型、模式、输出数、消费者数、复用数、重试来源、成功/失败和供应商返回费用。
- 供应商没有返回权威费用时记录 `null`，禁止用 0 伪装无费用。
- 费用只进入后台账本，不在生成页面要求用户确认。

图片模型不在方案文档中直接写死为某一个供应商型号。候选模型必须用同一组背景、单主体和 2×2/2×3 合图样例做离线 A/B 验证，记录单次价格、一次通过率、OCR 失败率、切割成功率和有效素材成本。只有“每个最终可用素材的实际成本”更低且质量门槛通过，才允许切换生产默认值；未经这组验证，不因官方宣传或主观观感自动更换模型。

## 8. 阻断式质量门槛

质量检查按从便宜到昂贵的顺序执行：

1. JSON Schema、必填字段、内容覆盖率和占位文字扫描。
2. 图片 OCR、尺寸、比例、透明度和消费关系检查。
3. PPTX ZIP/OOXML、页数、空页、空占位符、模板示例文字检查。
4. WPS/PowerPoint 真实渲染、逐页 PNG、溢出和越界检查。
5. 整稿联系表统一性检查。
6. 只有程序无法判断的失败页才发送给视觉模型，不发送整稿。

质量状态：

```text
pending → rendering → passed / failed
passed → 用户编辑 → stale
```

只有 `passed` 才能显示正式 PPTX 下载。用户编辑后必须重新导出和复验。

## 9. 无图优先验收

先使用 `imagePolicy=disabled` 和模拟模型跑通六类演示：幼儿认知、幼儿互动、幼儿故事、家长会、教师教研、园务总结。模拟数据只存在测试夹具中，不进入生产代码。

无图基线必须验证：

- 页数严格等于测试大纲；
- 页面序列不固定；
- 六类演示布局序列明显不同；
- 相邻页面不机械重复；
- 所有文本可编辑；
- 示例文字、图片描述、Prompt、Lorem 数量为 0；
- 中文标题和正文不溢出；
- WPS/PowerPoint 均可打开并完整渲染。

无图基线通过前，不执行真实图片模型调用。之后再逐步开启背景、图片框、透明主体和 Sprite sheet 验收。

## 10. 已落地的基础能力

- Presenton V2 独立 API、编辑器和导出运行时已接通，无需 Docker。
- 图片 Prompt 已强制执行无文字契约。
- 图片策略已持久化为 `disabled/minimal/standard`。
- 随机布局兜底已删除，布局数量和索引严格校验。
- 内容契约、布局容量和媒体兼容检查已接入。
- 全稿素材规划、复用、合图、裁切、透明背景处理已接入。
- Windows 本地 OCR 已接入，图片文字失败只重试该素材。
- 资产调用追踪和重试链已持久化。
- PPTX 正式导出已接入本地结构门槛，失败返回 422。
- 演示文稿质量状态已持久化，编辑后自动变为 `stale`。

这些基础能力不等于模板库已经验收完成。模板只有经过逐页中文 hydration、真实渲染和视觉审查后才能标记为 `passed` 并进入生产选择池。
