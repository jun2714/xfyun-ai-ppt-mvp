# 007 通用幼儿园 AI PPT 平台主规格

## 1. 产品目标

输入主题、受众、年龄、使用场景、页数、目标、约束和可选资料，生成一份结构合理、视觉完整、在线可编辑、可导出为可编辑 PPTX 的演示文稿。

产品覆盖幼儿园全部演示场景，但任何具体场景都只能作为输入数据或测试样本，禁止成为生产代码分支。

## 2. 产品流程

1. 用户输入 Brief 或上传资料。
2. 系统单次生成整份 Narrative Outline。
3. 用户编辑并确认大纲。
4. 系统批量生成 Deck Design Plan 和每页 Page Design Intent。
5. 构图引擎为每页产生多个通用组合候选并评分。
6. 素材规划器只为最终候选解析、复用或生成图片。
7. 同一 Scene Graph 同时驱动网页预览和 PPTX 导出。
8. 规则质量门检查全部页面；视觉模型只检查特殊页和低置信度页。
9. 最多进行一次局部修复，不自动重跑整份 PPT。
10. 用户在类 WPS 编辑器中修改、替换布局、替换图片并导出。

## 3. 核心原则

- AI 决定表达意图，不输出坐标、CSS、PPTX 代码。
- 代码负责约束、求解、评分、可编辑渲染和确定性导出。
- 页面不是固定模板，而是由通用布局原语组合出的树。
- 主题不是三个预设皮肤，而是可持久化的 Design Token Set。
- 图片不是按页生成，而是由最终构图中的 Media Placement 触发。
- 预览与导出只有一个事实来源：Scene Graph。
- 质量分为 Content、Design、Coherence、Export 四个维度。
- 所有付费调用均有显式 job、用量记录、幂等键和禁止自动重试规则。

## 4. 明确禁止

- 禁止 `scenario/title/pageNumber → layout`。
- 禁止 `role → 固定坐标/固定模板`。
- 禁止只读取 `blocks[0]`。
- 禁止每页固定一个标题区、一个正文区、一个图片区。
- 禁止模型直接输出坐标、Tailwind、HTML、SVG 或 PptxGenJS 代码进入生产渲染。
- 禁止先生成全部图片再决定布局。
- 禁止把整页 AI 图片作为可编辑 PPT 的默认方案。
- 禁止未进入 Scene Graph 的生成素材通过质量门。
- 禁止只凭“无越界、可导出”宣布视觉验收通过。
- 禁止用具体业务案例训练生产分支或模板映射。

## 5. 不属于有害写死的内容

以下属于稳定工程约束，可配置、可测试并集中管理：

- 支持的文件类型、PPTX 规范和 MIME；
- 可读字号下限、对比度下限和画布边界；
- 模型图片尺寸网格；
- API 请求大小、超时、最大页数；
- Scene Graph 和领域协议的版本号；
- 布局原语的语义，例如 Stack、Grid、Overlay、Flow、Anchor。

它们不能包含具体主题、页面文案或业务场景判断。

## 6. 成本目标

- 大纲：一次批量文本调用。
- 大纲确认后设计规划：一次批量结构化文本调用。
- 图片：只生成最终已放置且无法复用的素材。
- 视觉复核：规则低分页、封面、章节、全屏图、对比/揭晓等高风险页面进入一张联系表，单次多模态调用。
- 修复：最多一次，仅修改失败页面的设计意图或构图候选。
- 任何失败均不自动进行新的付费调用。

## 7. 验收标准

- 任意三个未进入生产代码的新主题可以完成同一流程。
- 同一套内容改变画布比例后重新求解，不依赖固定坐标。
- 页面可拥有多个内容组、多层级文本和多个媒体关系。
- 同一 Deck 中页面节奏有变化，但主题、字体、色彩和装饰语言一致。
- 所有生成图片都被最终页面引用；未放置素材调用数为零。
- 背景图自动生成文字安全区、遮罩与对比保护。
- 规则质量门覆盖所有页面；高风险页有视觉复核记录。
- PPTX 文本、形状、图表和图片保持独立可编辑。
- 网页预览与 PPTX 渲染来自同一 Scene Graph，语义指纹一致。
- 在 PowerPoint 与 WPS 中完成打开、逐页渲染和导出验证。

## 8. 外部研究依据

- Presenton：提示词/文档输入、可编辑器、自定义 HTML/Tailwind 模板、多模型和可编辑 PPTX。
- Gamma：页面为可调整的编辑单元，支持主题、图片来源、局部布局与单页重新生成。
- PPTAgent：参考演示分析、编辑式生成，并分别评价内容、设计和连贯性。

本项目借鉴它们的流程，不复制其模板绑定或技术栈。
