# 008 幼儿园全场景 PPT 成品质量规格

## 1. 目标

008 的目标不是复刻参考 PPT，而是让 SparkDeck 稳定生成达到同一“成品感等级”的原创幼儿园演示文稿：叙事完整、页面有视觉重点、原生形状参与设计、图片用途正确、跨页节奏自然、可在线编辑并导出可编辑 PPTX。

参考文件仅作为质量标尺。禁止复制或运行时读取其中的文字、图片、颜色值、字体、坐标、页面结构、母版、形状或动画。

## 2. 参考质量审计

参考 PPT 共 17 页，16:9。可观测特征如下：

- 叙事形成完整闭环：引入 → 认识 → 提问 → 揭晓 → 记忆 → 匹配 → 回顾 → 结束。
- 第 8/9、10/11、12/13、14/15 页形成四组“设置问题 → 下一页揭晓”的跨页节拍，而不是把问题和答案挤在同一页。
- 正文页可见中文约 23–48 字，单页只承担一个主要教学动作。
- 字号证据约为 20–76 pt；主体标题明显大于正文，幼儿观看距离下仍可辨认。
- 除封面外，图片通常占页面约 14%–34%，与原生文字、圆形底板、标签、提示条和装饰形状共同构成页面。
- 同一角色在不同页面复用，保持身份和画风一致；封面使用完整场景，正文主要使用独立主体素材。
- 同一套颜色、圆角、装饰和字体贯穿全稿，但视觉重点随页面任务变化。
- 参考文件自身存在画布外装饰对象，因此 008 只学习可见效果，不继承其结构问题。

这些是抽象质量指标，不是允许复制的模板规则。

## 3. 007 当前缺口

### P0：不补齐就无法生成正常成品

1. **缺少 Deck 级叙事节拍模型**
   - 当前只有独立 `NarrativePage` 和弱 `continuityLinks`。
   - 无法明确表示章节、铺垫/揭晓页对、回忆前后状态、观众动作和跨页递进。

2. **缺少跨页构图连续性**
   - 当前只惩罚相邻页面轮廓重复。
   - 无法要求两个关联页面保留共同对象的位置，仅改变答案、缺失项或连线。

3. **候选构图表达力不足**
   - 当前生产代码只有 `editorial / stage / sequence / mosaic` 四种策略。
   - 它们能避免越界，但不能根据实体集合、选项关系、配对关系、状态差异和视觉焦点生成足够丰富的原创构图。

4. **素材一致性只停留在复用键**
   - `continuityKey` 可以缓存，但没有角色身份、基础素材、变体、透明背景、风格一致性和质量检查协议。
   - 容易出现同一角色每页长得不一样，或背景图、主体图、抠图用途混乱。

5. **质量检查没有以最终 PPTX 为准**
   - 当前视觉联系表由简化 SVG 渲染，不等同于真实网页和 PPTX 渲染。
   - 文本测量仍是字符宽度近似；PPTX 导出还允许 `shrink`，可能静默缩小字体。
   - 当前修复只是切换到下一个候选，没有针对问题生成新的约束候选。

6. **没有真实成品验收门**
   - 当前测试验证结构、成本和导出，不验证真实幼儿园成品质量。
   - 技术 QA 样例不能作为产品验收稿。

### P1：影响在线编辑完整性

- 缺少拖拽缩放手柄、多选、对齐、添加/替换图片。
- 缺少新增、复制、删除、排序页面。
- 缺少主题级字体、颜色、形状语言编辑。
- 缺少单页重新设计与单素材重新生成入口。

## 4. 008 必须提供的能力

### 4.1 叙事与教学节拍

- 大纲必须包含 Deck 级 `NarrativeArc`、章节和跨页关系。
- 每页必须有一个主要沟通任务、一个受众结果和可选受众动作。
- 支持用通用语义表达：铺垫/揭晓、观察/回答、记忆/变化、比较、配对、递进和回顾。
- 语义只能影响候选约束与评分，禁止直接映射固定坐标或固定模板。
- 需要揭晓的内容必须分成独立页面状态；不得在问题页提前显示答案。

### 4.2 原创视觉语法

- Deck Design Plan 必须产出字体层级、语义色板、形状语言、装饰语法、图片语言、留白和节奏规则。
- 原生 PPT 元素必须参与设计，不能只做“背景图 + 文本框”。
- 装饰必须来自通用可参数化原语，不得含业务名称或参考文件坐标。
- 同一 Deck 保持视觉一致，同时至少形成四种可区分的页面轮廓。
- 允许一组内容连续页保持系列感，但不得让整套 PPT 都使用同一轮廓。

### 4.3 关系驱动构图

- 候选生成必须读取内容数量、内容层级、关系图、媒体角色和跨页约束。
- 构图树继续只使用 Canvas、SafeArea、Stack、Grid、Flow、Overlay、Anchor、Frame、Text、Shape、Image、Chart、Connector 等原语。
- 不新增“动物页、家长会页、目录页”等业务模板。
- 候选数量自适应：至少产生两个有效候选，以“新增候选没有带来足够结构差异”为停止条件，并设置可配置的工程上限防止无限搜索。禁止把固定候选数量当成页面类型规则。
- Deck 级求解同时评价单页适配、相邻节奏、跨页连续性和整稿一致性。

### 4.4 素材系统

- 版式确定后，先生成全 Deck `AssetBundlePlan`，再进行图片调用。
- 区分 `full-bleed-background / scene / subject / transparent-cutout / detail / evidence`，禁止角色自动互换。
- 同一视觉实体只能有一个基础身份；后续页面复用基础素材或明确生成受控变体。
- 透明主体必须验证 alpha/背景干净度；全屏背景必须验证比例、焦点和文字安全区。
- 图片提示词、图片说明和生产元数据永远不得进入可见文本。
- 图片调用按唯一素材计费，不按页计费；未放置素材调用数必须为零。

### 4.5 渲染和导出一致性

- Scene Graph 仍是唯一事实来源。
- 网页预览、PNG 质检和 PPTX 导出必须使用同样的文字换行、裁剪、层级和透明度语义。
- 禁止导出器静默缩小字号；不合适时应缩短文案或重新构图。
- 文字、形状、连接线、图片和图表必须保持独立可编辑。
- PowerPoint 与 WPS 的逐页渲染均需通过。

### 4.6 质量闭环

- 规则检查覆盖：内容遗漏、制作语言、真实字体度量、换行、碰撞、裁剪、清晰度、透明素材、对比度、视觉密度、页面轮廓重复、跨页状态差异和素材一致性。
- 视觉复核输入必须来自最终 PPTX 或与最终导出同构的高保真渲染，不得继续使用简化 SVG 作为最终证据。
- 一次视觉调用同时查看整稿低分辨率联系表和高风险页高分辨率截图。
- 修复必须根据问题形成新的结构化约束，只重算失败页；不得机械换下一个候选后直接宣布完成。
- 修复后必须重新导出、重新渲染、重新检查。

## 5. 成本纪律

- 大纲一次批量文本调用。
- 设计与跨页计划一次批量文本调用。
- 图片仅针对唯一且已放置素材调用；相同实体优先复用。
- 视觉检查最多一次批量调用；失败不自动产生第二次付费调用。
- 离线规则、模拟模型和本地渲染全部通过前，不允许启动真实付费基准测试。
- 后台记录每个调用的模型、用途、token、图片数、缓存命中和人民币估算；前台不显示费用确认步骤。

## 6. 非复制约束

008 实现和测试必须满足：

- 不把参考 PPT 加入代码仓库、运行时目录或测试夹具。
- 不读取参考 PPT 作为生成时模板。
- 不复制其文字、动物角色、森林图片、页面坐标、形状尺寸、页面顺序、色值或字体。
- 不创建“参考第 N 页 → 新页面”的映射。
- 只允许在本规格中保留聚合统计和抽象质量规律。
- 架构守卫必须扫描业务词、参考文件名、固定坐标映射和页面克隆逻辑。

## 7. 008 验收标准

### 7.1 基准稿

至少生成三份未进入生产代码的新 Brief：

1. 幼儿课堂活动：验证故事/观察/互动/揭晓/回顾节奏。
2. 家长沟通：验证信息层级、照片或插图与结论表达。
3. 教师或园务汇报：验证数据、流程、案例和行动建议。

测试主题不得使用森林、动物认知或参考稿素材。

### 7.2 成品指标

- 页数严格符合 Brief，且每页标题非空、无提示词和制作说明。
- 至少 90% 页面有明确视觉锚点；不要求每页生成图片。
- 正文页文字密度符合受众和观看距离；幼儿课堂基准正文原则上不低于 20 pt，标题原则上不低于 40 pt。
- 对 15 页以上的课堂基准稿，以“四种以上可辨认轮廓”作为测试目标；生产求解不得为了凑数量强制换版。除具有明确连续性约束的系列页外，连续三页完全同构必须产生质量警告并记录原因。
- 所有铺垫/揭晓页对通过状态检查，问题页不泄露答案。
- 相同实体风格和身份一致，且所有生成素材被实际引用。
- 背景、主体和抠图角色使用正确，无小图硬贴、错误拉伸和突兀边框。
- 规则检查无 error；视觉复核无 critical/error。
- 最终 PPTX 在 PowerPoint/WPS 打开正常，逐页截图无溢出、错误遮挡、糊图、错误裁剪和不可读文字。
- 用户能在网页和 PPTX 中编辑文字、移动/缩放元素、替换图片并导出。

### 7.3 完成定义

只有三份真实基准稿及其逐页渲染证据全部通过，008 才能标记完成。单元测试、技术 QA PPT 或接口成功不能替代成品验收。

## 8. 防错合同

008 的实现必须同时遵守 [防硬编码与代码注释规范](./guardrails.md) 和 [完整验证矩阵](./verification.md)。二者属于本规格的强制组成部分，不是建议。

任何阶段出现以下情况必须停止交付：

- 关键产物缺失或上游哈希不一致；
- 关联页状态无法验证；
- 可见文字含提示词、图片描述、占位符或生产说明；
- 必需素材未解析、媒体角色冲突或生成素材未使用；
- Scene、网页预览与最终 PPTX 之间存在未解释差异；
- 最终 PPTX 没有逐页渲染证据；
- 架构守卫发现业务词到排版的映射、固定坐标集合或参考文件复用；
- 付费调用次数超过当前 Job 明确允许的上限；
- 测试、类型检查、构建、规则质检或视觉质检失败。
