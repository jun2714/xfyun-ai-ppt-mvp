# 008 完整验证矩阵

## 1. 验证原则

008 不承诺“代码永远不可能出错”，而是要求每类已知风险都有预防、检测、失败处理和证据。任何必需证据缺失都视为未完成。

验证分为：Schema、单元、属性、集成、失败注入、真实模型、视觉、PPTX/WPS、人工验收和架构扫描。

## 2. 分阶段质量门

| 阶段 | 必须通过 | 失败处理 |
|---|---|---|
| Brief | Schema、页数、语言、素材引用 | 400，禁止启动 Job |
| Narrative | JSON、引用、章节、谓词、字数、可见文案 | Job 失败，不自动重试 |
| Design | 字体、色板、媒体角色、关系对齐、无坐标语言 | Job 失败，不自动重试 |
| Composition | 必需内容覆盖、无越界、无非法重叠、可读字号、Trace 完整 | 淘汰候选；无候选则失败 |
| Asset | 唯一身份、比例、分辨率、alpha、引用、缓存 | 单素材失败，不丢失其他素材 |
| Scene | Schema、revision、上游哈希、节点引用、编辑命令 | 冲突返回 409，不覆盖新版本 |
| Rule Quality | 内容、设计、连贯、导出规则 | 阻止视觉复核与导出 |
| Visual Quality | 整稿节奏、高风险页、图片一致性 | 生成 RepairConstraint，不自动付费重试 |
| PPTX Export | 原生对象、字体、备注、媒体、连接器、哈希 | 禁止交付 |
| PPTX Render | PowerPoint/WPS 可见结果和 Scene 差异 | 禁止交付并定位页面/节点 |

## 3. Schema 和引用测试

- 所有 ID 唯一。
- PageLink 页面、sourceId 和约束引用存在。
- `conceal/introduce/change` 引用的页面属于同一关联组。
- 必需内容组至少被一个 Scene Node 引用。
- AssetIdentity 与 MediaPlacement 的角色一致。
- 所有下游 upstreamHash 等于当前上游 contentHash。
- 旧 revision 命令不能覆盖新 Scene。
- 007 与 008 Schema 不得在同一生产对象中混用。

## 4. 文案测试

- 标题非空且不出现异常换行。
- 页面可见字段不包含 prompt、negative prompt、safe area、layout、image description、placeholder、制作说明和模型错误文本。
- speaker notes 不被编译为可见节点。
- 问题状态不包含被 conceal 的答案源。
- 所有文字符合受众、年龄和语言要求。
- 超出字数预算时先压缩文案或换构图，不静默缩小到阈值以下。
- 对输入中的提示注入文本进行隔离，模型不能改变输出协议和生产规则。

## 5. 构图测试

### 5.1 单元测试

- 每种原语在横版、竖版、方形画布上的边界计算。
- Stack/Grid/Flow 的间距、grow、min/max 和对齐。
- Overlay/Anchor 的层级和安全区。
- 文本测量、换行、段落间距和字体 fallback。
- contain/cover 裁剪和焦点映射。
- Connector 位于节点后方并不穿越标签。

### 5.2 属性测试

随机生成 1–12 个内容组、0–8 个媒体、不同长度文字和不同画布比例，验证：

- 求解终止；
- 无 NaN/Infinity/负尺寸；
- 必需源不丢失；
- 候选结构存在真实差异；
- 分数稳定且不依赖对象遍历随机顺序；
- 同一 seed 可重放；
- 不读取主题关键词决定布局。

### 5.3 跨页测试

- preserve 对象保持身份和规定属性。
- conceal 对象在指定状态完全不可见。
- introduce 对象只在指定页面出现。
- change 只改变允许的属性。
- 关联组重新设计时共同求解。
- 删除关联页面时给出明确冲突或同时更新谓词。

## 6. 素材测试

- 构图选择前图片调用数为零。
- 相同身份、角色、比例和变体命中缓存。
- 不同角色不能误用同一缓存结果。
- 透明主体检测 alpha、脏边、背景残留和过大空白。
- 背景验证比例、焦点、安全区和清晰度。
- 图片下载验证 MIME、尺寸、超时和内容长度。
- 低分辨率、损坏、空文件、错误格式和远程 404 被拒绝。
- 所有生成资产都有最终引用；未使用资产为 error。
- 替换一张图片只失效相关 Scene/质量/导出，不重新生成无关图片。

## 7. 模型坏响应测试

模拟以下响应：

- 非 JSON；
- 截断 JSON；
- 多余 Markdown 代码块；
- 页数错误；
- 重复 ID；
- 引用不存在内容；
- 返回坐标、CSS、HTML、SVG、PPTX 代码；
- 把图片描述放入可见文字；
- 问题页泄露答案；
- 媒体角色和描述冲突；
- 响应超时、429、500 和连接中断。

每种情况均验证：错误码准确、没有自动付费重试、没有部分脏状态、usage 记录是否产生费用准确。

## 8. API、并发和持久化测试

- 相同 idempotencyKey 返回同一 Job，不重复调用模型。
- 不同请求不能错误共享 Job。
- 两个编辑命令使用相同 expectedRevision 时只有一个成功。
- 服务重启后 Presentation、Job、usage、资产和 revision 一致恢复。
- Job 在各阶段崩溃后可以识别为失败或安全恢复，不能永久 running。
- 原子保存失败不改变旧状态。
- 大请求、非法文件、路径穿越和 MIME 欺骗被拒绝。
- API/日志不回显 `.env`、API Key 和图片 base64。

## 9. 质量规则测试

- 空标题、标题换行、正文溢出、低对比、非法重叠、越界和过密。
- 文本覆盖图片但没有保护层。
- 背景错误缩成小卡片；主体错误铺满整页。
- 重复轮廓、缺少视觉锚点和跨页跳变。
- 同一身份出现明显画风或外观漂移。
- 问题/答案同时出现或关联页共享对象错位。
- 低清图、错误裁剪、拉伸、透明脏边和图片加载失败。
- 制作语言、提示词和图片描述泄漏。
- Scene render 与 PPTX render 差异超过阈值。

## 10. 渲染与导出测试

- 每种 Scene Node 导出为独立可编辑对象。
- 字体、字号、粗细、颜色、对齐、行距、段距和内边距一致。
- 形状圆角、描边、透明度和层级一致。
- 图片 contain/cover、裁剪和透明通道一致。
- 图表数据、标签、图例和颜色一致。
- 连接线先于实体节点创建，端点和箭头正确。
- speaker notes 保留且不出现在页面。
- 禁止 exporter 重新决定布局或静默 shrink。
- 导出的 ZIP/PPTX 结构有效，所有关系和媒体存在。
- PowerPoint 与 WPS 分别打开、保存和重新渲染。

## 11. 视觉验收

### 11.1 每页

- 第一眼能识别视觉焦点和主要结论/任务。
- 标题、正文、媒体和形状形成清楚层级。
- 图片与当前信息有关，不是装饰性乱贴。
- 没有突兀小图、错误边框、压缩变形、糊图和裁剪主体。
- 幼儿页面观看距离下可读；家长/教师页面信息密度适合其场景。

### 11.2 整稿

- 叙事连续，前一页为后一页建立需要。
- 视觉语言一致但轮廓不机械重复。
- 关联页连续，变化项明确。
- 同一实体身份和画风一致。
- 开头建立目标，结尾完成回顾、行动或讨论，不突然结束。

### 11.3 证据

- 完整 PPTX；
- 每页真实渲染 PNG；
- 整稿联系表；
- 规则质量报告；
- 视觉质量报告；
- Scene/PPTX 差异报告；
- usage ledger；
- 硬编码扫描报告。

## 12. 真实基准执行顺序

1. 全部离线测试通过。
2. 使用模拟模型生成三类完整 Scene，验证无付费路径。
3. 只启动一份真实幼儿课堂基准稿，限制文本为两次批量调用、视觉为一次批量调用，图片按唯一已放置素材调用。
4. 逐页修复通用问题，禁止为该主题添加生产分支。
5. 架构守卫和未见 Brief 回归通过后，再执行家长沟通和园务汇报基准。
6. 三份成品由人工确认后才标记 008 完成。

## 13. 发布阻断条件

出现任一情况不得发布：

- 测试失败、跳过或只在单机偶然通过；
- 任何真实页面没有最终 PPTX 截图；
- 任何错误级质量问题未解决；
- 参考素材、测试主题或业务布局分支进入生产代码；
- 图片或模型调用无法对账；
- 自动付费重试发生；
- 注释与实现不一致；
- `.env` 被修改、提交或回显；
- PowerPoint/WPS 任一目标环境验证失败。
