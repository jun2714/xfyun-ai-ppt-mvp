# 009 AI PPT 端到端交付差距规格

## 1. 文档状态

009 当前只做差距确认，不授权修改生产代码、重跑生成任务或调用付费模型。

008 没有完成。已经完成的离线模块、单元测试和 Office 技术验证不能替代以下产品结果：

`用户输入基本信息 → 得到可确认的大纲 → 自动生成完整演示 → 在线预览与编辑 → 导出正常 PPTX`

009 的唯一完成结果是：普通用户从产品页面输入一个此前未写入代码或提示词的幼儿园演示需求，能够稳定得到内容正确、页面有设计、图片使用正确、可编辑、可预览、可导出的完整 PPTX。

“可以导出测试 PPT”“接口返回成功”“没有越界”“模拟模型通过”都不等于 009 完成。

## 2. 已确认的事实

### 2.1 已有但不能代表产品完成的能力

- 008 领域协议、Scene Graph、素材身份、候选构图、质量报告和 Render Evidence 已有基础实现。
- 手写离线 Scene 可以导出 PPTX。
- 离线 QA PPTX 已经由 WPS 和 PowerPoint 渲染，技术差异分数低于当前阈值。
- 生产 TypeScript 没有发现幼儿园具体主题到固定坐标的直接分支。
- 图片在构图候选确定后才请求，并按素材身份复用。
- `.env` 得到保留，费用确认不进入前台流程。

这些证据只证明部分基础设施可运行，不证明真实 AI 生成链路可交付。

### 2.2 已确认的失败

最终验收在加载阶段失败：根目录验收脚本直接导入仅声明在 `apps/api` 工作区内的 `sharp`，pnpm 严格依赖隔离导致 `ERR_MODULE_NOT_FOUND`。

失败前没有读取业务输入、没有调用文本模型、没有调用图片模型、没有生成 PPT，也没有产生费用。

这不是 PPTX 导出器故障，但证明发布验收入口没有经过真实冷启动预检。

### 2.3 不能继续使用的完成说法

在三份真实、外部、未见 Brief 完成全链路之前，禁止声称：

- “AI PPT 已经可以生成”；
- “008 已完成”；
- “已经达到参考质量”；
- “只差模型效果”；
- “只是一个验收脚本小问题”；
- “架构测试通过，所以不会再写死”。

## 3. P0 差距：不解决就不能生成正常 PPT

### P0-01 缺少始终可运行的产品主链

当前各模块分别有测试，但没有一条在干净进程中持续执行并交付产物的权威命令。验收脚本首次运行即因依赖解析失败，说明构建成功与真实运行成功被错误地当成同一件事。

009 必须提供唯一、受版本控制、从冷启动执行的交付入口，并在任何模型调用前完成依赖、配置、目录、Office、字体和输出权限预检。

### P0-02 真实文本模型协议未被证明

当前 Narrative 与 Design 都依赖模型一次返回严格 JSON。模拟响应通过不能证明当前 DMX 文本模型能够稳定满足：

- JSON 无 Markdown 包裹；
- 页数准确；
- ID 唯一且引用存在；
- 标题是观众可见标题，不是制作说明；
- 图片描述不进入页面文字；
- PageLink 的 conceal/introduce 状态正确；
- Design 不返回坐标、模板、HTML、SVG 或 PPTX 代码；
- 每个必需内容组都进入设计意图；
- 不虚构输入未提供的事实和数据。

当前没有真实响应样本、通过率、失败类型分布和模型之间的同协议对比证据。

### P0-03 没有对“标题是否像标题”做语义质量验证

当前主要检查标题非空、换行和制作语言，不能识别以下问题：

- 标题只是“展示某某”“介绍某某”等制作动作；
- 标题与正文重复；
- 标题没有说出本页结论、问题或活动动作；
- 标题不符合幼儿、家长或教师的语言水平；
- 连续页面标题高度同质；
- 家长会或园务页面只剩图片，没有必要的观点文字。

标题质量不能通过固定词表或页面角色模板解决，必须通过通用语义合同、确定性校验和有证据的视觉复核共同判断。

### P0-04 仍存在隐藏的统一构图骨架

008 已经移除具体业务模板，但当前构图树仍普遍共享：

`Canvas → Overlay → SafeArea → Frame → 标题区 + 内容区`

并且对少量内容存在“横向标题区”，对其他情况存在“纵向标题区”的通用分支。这不是“动物页、家长会页”写死，却仍是一种结构写死，会导致不同主题最终拥有相似骨架。

因此 008 不能宣称“没有固定排版”。它只是从业务模板写死退到了通用骨架写死。

009 必须让标题成为可参与构图关系的语义节点，而不是每页都先获得固定标题带。标题、主体、说明、媒体、图表和关系可以形成多种有效层级，但任何变化都必须来自内容图、设计语法和约束求解，不能来自主题名称、页码或页面角色。

### P0-05 视觉评分只能筛掉技术错误，不能证明设计质量

当前评分偏重占用率、中心位置、空白、内容覆盖和轮廓差异，仍不能可靠判断：

- 页面是否像一页完成设计的 PPT；
- 标题、主体和辅助信息是否形成自然视觉层级；
- 原生形状是否真正表达结构，而不是只有一块大底板；
- 字体、粗细、行距、段距和强调是否专业；
- 页面是否过于空、过于朴素或像调试稿；
- 相邻页面是否有节奏，而不是机械换方向；
- 图表、流程、目录、章节过渡是否具有演示语义。

离线 QA 联系表已经证明“无越界”仍可能非常朴素，因此当前质量分不能作为成品分。

### P0-06 WPS 风格的原生 PPT 设计语言不足

当前可导出文字、形状、连接线、图片和图表，但缺少正常演示设计所需的完整表达能力：

- 多层字体层级与局部强调；
- 富文本、项目符号层级、段前段后和可控行距；
- 章节页、目录、过程、比较、时间线、步骤、数据结论等通用语义组件；
- 形状组合、分组、图标、标签、编号、引导线和强调标记；
- 图片蒙版、焦点裁剪、渐变、叠色保护层和一致的图片处理；
- 表格、图表、流程与说明文字之间的语义关联；
- 整稿母题、页码、章节标识和连续但不重复的装饰系统。

这些不能实现成一组按页面角色选择的模板。它们必须是可组合原语和约束能力。

### P0-07 图片“生成成功”不等于“适合这页”

当前素材验证主要覆盖像素、比例和 alpha，尚未证明：

- 图片与页面观点或教学动作语义相关；
- 同一实体跨页外观和画风一致；
- 背景确实可以全屏使用且文字安全区有效；
- 主体图没有被当背景，背景图没有缩成小卡片；
- 抠图没有白边、脏边、过大空白或残留背景；
- 图片中没有错误文字、水印、标志和不适龄内容；
- 生成图片在网页与 PPTX 中采用同一裁剪焦点；
- 低质量图片能够阻止交付，而不是只产生 warning。

当前视觉复核只看到最终联系表，缺少素材身份对照、局部高清图和跨页一致性证据。

### P0-08 质量复核输入不完整

008 规格要求“整稿联系表 + 高风险页高清图 + 素材身份对照”，当前实现主要发送一张最终 PPTX 联系表。

联系表可以看整稿节奏，但容易漏掉：小字号、局部遮挡、错误裁剪、图片文字、水印、透明脏边和单个对象漂移。只用全局像素差异阈值也可能掩盖局部严重错误。

### P0-09 异步 Job 仍有覆盖新状态的风险

文件仓储使用原子替换，但没有聚合级 CAS、版本提交或进程间锁。当前只针对异步外部图片替换补过一次 revision 复查，以下长任务仍可能在等待模型或 Office 时持有旧状态：

- 大纲生成；
- 设计生成；
- 素材解析；
- 质量检查；
- 视觉复核；
- 导出渲染。

如果用户同时编辑，旧 Job 可能覆盖较新的 Scene、Outline、usage 或 asset 状态。文件原子写入只能防止半个 JSON 文件，不能防止合法旧版本覆盖新版本。

### P0-10 真实 PPT 交付门没有执行成功

目前不存在以下完整证据集合：

- 三份真实模型生成的原创 PPTX；
- 每页 WPS PNG；
- 每页 PowerPoint PNG；
- 网页预览截图；
- 规则质量报告；
- 视觉质量报告；
- 图片身份与调用账单；
- Scene/PPTX 差异报告；
- 双重硬编码扫描；
- 人工逐页确认记录。

缺少任何一项，都不能宣布完成。

## 4. P1 差距：能够生成后仍会影响正常使用

### P1-01 编辑器尚不是主流 PPT 编辑体验

当前编辑器具备部分移动、缩放、旋转、对齐和主题入口，但仍缺少或未证明：

- 可见缩放手柄、旋转手柄和对齐参考线；
- 键盘移动、删除、复制粘贴、多选框和快捷键；
- 元素分组、锁定、前移后移与图层面板；
- 富文本局部格式；
- 字体下拉、字号、粗细、颜色、行距和段落控制；
- 图片本地上传、素材库、焦点裁剪和透明处理；
- 图表数据编辑、表格编辑和连接线编辑；
- 备注编辑、演讲者视图和放映预览；
- 页面缩略图拖拽排序；
- 自动保存状态、保存失败提示和离开保护；
- 操作失败时保留编辑器，而不是整个页面切换成错误页。

### P1-02 单页重新设计仍可能破坏用户编辑

重新编译 Scene 可能重新生成整稿节点，用户手动移动、改字、替换图片后的 override 如何保留尚无完整合并协议。候选切换、单页重设计、主题变化和上游大纲变化之间的失效范围仍需逐项证明。

### P1-03 页面新增后与大纲和叙事脱节

手工新增、复制、删除页面主要修改 Scene；新增页面没有对应 NarrativePage、DesignIntent 和 PageLink 语义。它可以被导出，但未必能参加质量检查、重新设计和跨页约束。

### P1-04 输入产品缺少完整状态反馈

用户需要看到大纲生成、设计、构图、素材、质检和导出的明确进度与可操作错误。费用只进入后台是正确的，但后台仍应记录实际调用、缓存和失败成本，前台不能只显示“请求失败 500”。

### P1-05 来源材料能力尚未开放

Word、PDF、图片和旧 PPT 上传仍未形成完整的解析、引用、版权边界和事实来源链。没有来源时不能编造园务数据；有来源时必须能追踪内容来自哪里。

## 5. P2 差距：架构、成本和维护风险

### P2-01 Application Service 责任过多

当前平台服务同时协调项目、Job、幂等、规划、构图、素材、质量、编辑历史、导出、用量和持久化，已经接近 God Service，违反单一职责并增加状态覆盖风险。

009 应拆分用例与事务边界，但禁止为了“整洁”再次大规模重写已经可用的领域协议。拆分必须以主链可运行和回归证据为前提。

### P2-02 文件 JSON 不是可扩展项目存储

当前文件仓储适合本地开发，但把 Scene、Job、usage 和图片 base64 放入单个 JSON 会导致文件膨胀、并发覆盖、备份成本和读取延迟。009 需要明确本地开发仓储与生产仓储 Port 的边界；未经用户确认不得擅自引入或迁移数据库。

### P2-03 成本账本仍是估算

当前人民币费用依赖环境配置的单价和供应商返回 token，不能证明与 DMX 实际扣费一致。还缺少：

- Deck 级图片调用上限；
- Job 级最大总成本；
- 模型未返回 usage 时的可信估算标记；
- 成功返回但素材校验失败的成本分类；
- 人工单图重生和重复视觉检查的独立账目；
- 验收前后的余额或供应商账单对账。

费用继续只在后台统计，不在生成页面增加确认步骤。

### P2-04 外部图片安全仍需完整失败协议

已经增加 HTTPS、DNS 和私网地址阻断，但 DNS 失败、重定向、MIME 欺骗、压缩炸弹、证书错误和供应商临时地址过期仍需要明确错误码、测试和不污染状态的证据。

### P2-05 测试任务与实际状态不同步

008 `tasks.md` 的任务仍全部未勾选，而部分代码已经实现、部分只实现一半、部分从未验证。规格清单不能继续充当完成证明。

009 的每个任务必须链接到实际测试、报告或产物；没有证据只能标为“未证明”，不能凭代码存在勾选完成。

### P2-06 属性测试覆盖仍不足

当前属性测试增加了内容和媒体数量变化，但仍没有完整证明：

- 所有递归节点无 NaN、Infinity 和负尺寸；
- 对象输入顺序变化不影响稳定性；
- 相同 seed 完全可重放；
- 1–12 内容组与 0–8 媒体在所有文字长度下均有合理失败协议；
- 连接线不穿过标签；
- 复杂中文字体 fallback 一致；
- 多页 PageLink 组重新求解保持合法状态。

### P2-07 验收 Brief 不应固化在执行脚本

具体基准主题可以作为外部测试输入，但不应长期写在生产代码或通用验收执行器中。009 的验收器只读取外部 JSON Brief；每轮最终验收由用户或独立输入文件提供此前未见主题，并将输入哈希记入报告。

## 6. 硬编码重新定义

009 同时禁止三层写死。

### 6.1 业务写死

禁止主题、场景、年龄、班级、标题关键词、页面角色、页码或参考文件名称选择布局、图片槽、字体、颜色、构图树或提示词正文。

### 6.2 结构写死

禁止所有页面无条件共享同一个标题带、正文容器、图片容器或固定树形骨架。通用原语可以固定，页面树必须由内容关系和约束组合产生。

### 6.3 文案与提示词写死

生产代码不得包含具体演示标题、正文、图片描述、测试主题或供应商专用长提示词。模型合同必须位于外部、版本化、可替换的 Prompt Contract 中；合同只能描述输出协议、通用质量和禁止项，不能包含幼儿园具体主题答案或页面布局方案。

工程阈值、协议枚举、标准画布、Office 文件格式和安全限制不属于业务写死，但必须集中配置、解释依据并接受测试。

## 7. 009 完成定义

009 只有同时满足以下条件才算完成：

1. 冷启动预检和唯一交付命令成功。
2. 三份外部未见 Brief 分别覆盖幼儿课堂、家长沟通和教师/园务场景。
3. 每份都由真实文本模型生成大纲和设计，不使用手写 Narrative/Design 代替。
4. 图片只为最终放置的唯一素材生成，调用数和人民币费用可以逐项对账。
5. 每份都通过规则检查、一次批量视觉复核、WPS 和 PowerPoint 逐页渲染。
6. 每份都能在网页编辑并导出，编辑后导出保持一致。
7. 人工逐页检查确认内容、标题、图片、排版和整稿节奏均达到正常 PPT 水平。
8. 两次独立硬编码扫描均未发现业务写死、结构写死、参考内容复制或生产提示词泄漏。
9. 失败注入证明无自动付费重试、无旧状态覆盖、无半成品冒充成功。
10. 用户确认验收结果后，才允许标记 009 完成。

无法承诺“永远不会出现任何错误”。009 必须做到的是：错误在付费前尽量发现、在交付前必然阻断、错误码和费用清楚、失败不覆盖正确状态，并且任何完成声明都有可检查证据。
