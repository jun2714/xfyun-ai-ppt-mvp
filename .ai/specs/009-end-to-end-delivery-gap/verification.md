# 009 证据与验收矩阵

## 1. 证据等级

| 等级 | 含义 | 能否证明完成 |
|---|---|---|
| E0 | 代码存在、注释或设计说明 | 不能 |
| E1 | 单元测试或模拟模型测试 | 只能证明局部行为 |
| E2 | 本地集成测试和手写 Scene PPTX | 只能证明技术链 |
| E3 | 真实模型端到端产物 | 可以证明单次链路 |
| E4 | WPS、PowerPoint、浏览器和人工逐页证据 | 可以证明单份成品 |
| E5 | 三份外部未见 Brief 全部达到 E4，且双重扫描通过 | 才能申请完成 |

009 完成必须达到 E5，并由用户确认。

## 3. 预检验证

预检必须真正加载验收器全部模块，不允许只做语法检查。

验证以下失败均发生在付费调用之前：

- 缺少直接依赖；
- Prompt 文件缺失；
- `.env` 缺少 API Key；
- 模型/API 风格组合无效；
- 输出目录不可写；
- WPS 不可用；
- PowerPoint 不可用；
- 中文字体缺失且无 fallback；
- 外部 Brief Schema 错误。

每种情况要求 usage ledger 新增记录为零。

## 4. 模型验证

对 Narrative 和 Design 分别执行：

- 严格 JSON；
- 页数和 ID；
- 引用完整性；
- 可见文案；
- 生产语言；
- PageLink 状态；
- 媒体角色和身份；
- 禁止坐标和模板；
- 未提供事实不得编造；
- 一次调用、失败不重试。

不能通过人工修 JSON 后继续流程。模型原始响应失败就必须让 Job 失败。

## 5. 构图验证

测试输入从外部生成，覆盖不同内容数量、文字长度、媒体数量、关系图和画布。

必须证明：

- 没有主题、场景、年龄、页码和页面角色到布局的分支；
- 没有所有页面必经的固定标题带或固定图片槽；
- 必需内容不丢失；
- 所有节点边界有限、非负并位于合法区域；
- 文字达不到最小可读字号时明确失败或请求拆页；
- 候选有真实结构差异；
- 相同输入可重放；
- PageLink 关联页共同求解；
- 连接线和标签可读；
- 整稿不会连续机械重复。

## 6. 图片验证

对每个最终生成素材保存：

- identityId；
- requestHash；
- Prompt Contract 版本哈希；
- 模型；
- 角色；
- 目标比例；
- 技术校验；
- 语义校验；
- 最终放置页和节点；
- 缓存命中；
- 费用。

图片描述和完整提示词不得出现在 Scene 可见文字、PPTX 文字、网页 DOM 和错误页面中。

## 7. 并发验证

分别让以下 Job 在等待外部 I/O 时发生用户编辑：

- Narrative；
- Design；
- Asset Resolve；
- Visual Quality；
- Export Render；
- Manual Asset Regeneration。

旧 Job 只能提交到原 revision。冲突时：

- 新编辑保留；
- Job 明确失败；
- 已产生费用保留在账本；
- 未产生新自动调用；
- 不留下半成品成功状态。

## 8. 编辑器验证

使用真实浏览器完成：

1. 创建演示。
2. 生成并编辑大纲。
3. 确认大纲并生成演示。
4. 浏览所有页面。
5. 修改文字、字体、颜色和位置。
6. 上传并裁剪一张图片。
7. 复制、排序和删除非关联页。
8. 撤销和重做。
9. 质检。
10. 导出并在 WPS/PowerPoint 打开。

每一步保存截图和 Scene revision。页面不能因一个命令失败而丢失整个编辑上下文。

## 9. 成品视觉验证

每页人工检查：

- 第一眼能识别主要结论、问题或活动；
- 标题像观众标题，不像制作命令；
- 内容完整且没有图片描述；
- 字体、形状和布局具有正常 PPT 设计质量；
- 图片语义正确、角色正确、清晰且裁剪合理；
- 没有背景缩卡片、主体铺满、压缩变形和突兀边框；
- 页面不是空壳，也不是文字堆积；
- 幼儿、家长和教师分别符合其观看距离和信息密度。

整稿检查：

- 开头、展开、互动/论证、回顾和结束完整；
- 页面连续但不机械重复；
- 相同身份不漂移；
- 关联页状态合法；
- 原生元素和图片共同构成设计；
- 不依赖参考 PPT 的任何素材或结构。

## 10. 最终冻结规则

最终验收前记录 Git diff、配置哈希、Prompt Contract 哈希和外部 Brief 哈希。

验收启动后：

- 禁止修改生产代码、Prompt Contract、测试阈值和验收输入；
- 禁止重试付费模型；
- 禁止更换模型绕过失败；
- 禁止人工修正生成 JSON；
- 禁止删除失败证据；
- 失败后只展示报告，等待用户确认。

用户确认解除冻结后，修复必须进入新的 revision，并从预检重新开始。
